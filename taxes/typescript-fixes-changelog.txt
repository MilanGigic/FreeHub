1. actions/computeTaxes.ts
────────────────────────────────────────────────────────────────────────────────

PROBLEM (fix #1)
  Passing a single flat object into calculateSRBTaxes() failed TypeScript check:
  SRBTaxInputs is a discriminated union (MODEL_1 | MODEL_2 | PAUSAL | KNJIGAS).
  A object with model: SRBModel plus all optional fields does not assign to any member
  (e.g. KNJIGAS requires model: "KNJIGAS" literally, not SRBModel).

CHANGES
  • Import SRBTaxInputs from @/utils/taxCalculatorSRB (in addition to calculateSRBTaxes).
  • Added function toSrbTaxInputs(input: SRBTaxInput & { annualGross: string }): SRBTaxInputs
    - Builds shared fields: annualGross (parsed number), isAlreadyEmployed, isUnder40
    - switch (input.model):
        MODEL_1  → { ...shared, model: "MODEL_1" }
        MODEL_2  → { ...shared, model: "MODEL_2" }
        PAUSAL   → { ...shared, model: "PAUSAL", pausalMonthlyBill, rollingAnnualGross }
        KNJIGAS  → { ...shared, model: "KNJIGAS", monthlyExpenses ?? 0, monthlySalary }
  • Serbia branch now calls:
        calculateSRBTaxes(toSrbTaxInputs(input))
    instead of one object with model + every field at once.

BEHAVIOR
  Unchanged at runtime; only types / call shape corrected. PAUSAL still passes undefined
  pausalMonthlyBill when missing (handled inside calcPausal). KNJIGAS still defaults
  monthlyExpenses to 0 when undefined.

PROBLEM (fix #2)
  Return object included modelRecommendation but TaxResult type had no such field;
  calculateTaxes return type is Omit<TaxResult, "netProfit" | "warnings">.

CHANGES
  • Kept mapping: modelRecommendation: result.modelRecommendation (Serbia branch).
  • Fix completed in useTaxProfileStore.ts (see file 3 below).

2. utils/taxCalculatorSRB.ts
────────────────────────────────────────────────────────────────────────────────

PROBLEM
  PausalInputs required pausalMonthlyBill: number, but computeTaxes intentionally passes
  undefined when pausal bill is unknown; calcPausal() already treats that as invalid
  and returns null with a warning.

CHANGES
  • PausalInputs.pausalMonthlyBill changed from required number to optional:
        pausalMonthlyBill?: number
  • Comment updated: omitted bill → zeroed result + warning (via calcPausal null path).

BEHAVIOR
  Aligns types with existing runtime logic; no calculator math changed.

3. lib/store/useTaxProfileStore.ts
────────────────────────────────────────────────────────────────────────────────

PROBLEM
  modelRecommendation on Serbia tax result was not part of TaxResult, so TypeScript
  rejected it on the object returned from calculateTaxes().

CHANGES
  • Added optional field to TaxResult:
        modelRecommendation?: {
          recommended: "MODEL_1" | "MODEL_2";
          reason: string;
        };
  • JSDoc: "MODEL_1 vs MODEL_2 break-even hint (Serbia frilenser only)"

BEHAVIOR
  initialTaxResult unchanged (field optional, omitted). US and non-frilenser SRB paths
  do not set it; MODEL_1 / MODEL_2 Serbia paths populate it from calculateSRBTaxes.
